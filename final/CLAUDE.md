# AI助手核心规则：
-如果你的任务是维护和升级一个工程，请保证代码风格的延续。
## 三阶段工作流

### 阶段一：分析问题

**声明格式**：`【分析问题】`

**目的**
因为可能存在多个可选方案，要做出正确的决策，需要足够的依据。

**必须做的事**：
- 理解我的意图，如果有歧义请问我
- 搜索所有相关代码
- 识别问题根因

**主动发现问题**
- 发现重复代码
- 识别不合理的命名
- 发现多余的代码、类
- 发现可能过时的设计
- 发现过于复杂的设计、调用
- 发现不一致的类型定义
- 进一步搜索代码，看是否更大范围内有类似问题

做完以上事项，就可以向我提问了。

**绝对禁止**：
- ❌ 修改任何代码
- ❌ 急于给出解决方案
- ❌ 跳过搜索和理解步骤
- ❌ 不分析就推荐方案

**阶段转换规则**
本阶段你要向我提问。
如果存在多个你无法抉择的方案，要问我，作为提问的一部分。
如果没有需要问我的，则直接进入下一阶段。

### 阶段二：制定方案
**声明格式**：`【制定方案】`

**前置条件**：
- 我明确回答了关键技术决策。

**必须做的事**：
- 列出变更（新增、修改、删除）的文件，简要描述每个文件的变化
- 消除重复逻辑：如果发现重复代码，必须通过复用或抽象来消除
- 确保修改后的代码符合DRY原则和良好的架构设计
- 如果你认为上网搜索能帮助你更好的制定方案，必须主动的上网搜索
  

如果新发现了向我收集的关键决策，在这个阶段你还可以继续问我，直到没有不明确的问题之后，本阶段结束。
本阶段不允许自动切换到下一阶段。

### 阶段三：执行方案
**声明格式**：`【执行方案】`

**必须做的事**：
- 严格按照选定方案实现
- 修改后运行类型检查
- 在最后询问我是否需要编辑某一个md文件（在我没有额外说明的情况下不可以额外编写md文件）

**绝对禁止**：

- ❌ 提交代码（除非用户明确要求）
- 启动开发服务器
- 没有得到我的允许擅自生成markdown文件和python脚本

如果在这个阶段发现了拿不准的问题，请向我提问。

收到用户消息时，一般从【分析问题】阶段开始，除非用户明确指定阶段的名字。

如果你的任务是从0开始创建新的工程项目，在新项目中应用此风格，检查：
✅ 项目结构
[ ] include/src 目录结构一致
[ ] 按模块划分（不超过7个顶层模块）
[ ] 配置文件独立存放
[ ] README.md 和部署文档齐全
✅ 命名规范
[ ] 类名：PascalCase
[ ] 函数名：camelCase
[ ] 成员变量：snake_case_（下划线后缀）
[ ] 局部变量：snake_case
[ ] 常量：UPPER_CASE 或 kConstantName
[ ] 文件名：snake_case.hpp/cpp
✅ 代码组织
[ ] 所有代码在命名空间内
[ ] 头文件有 include guard
[ ] 构造函数使用初始化列表
[ ] public/protected/private 明确分组
✅ 注释与文档
[ ] 公共接口有 Doxygen 注释
[ ] 复杂算法有说明注释
[ ] 配置参数有范围/单位说明
[ ] 关键决策有 TODO/FIXME 标记
✅ 错误处理
[ ] 边界条件检查（nullptr、empty、范围）
[ ] 有备用方案或降级策略
[ ] 错误信息清晰（包含原因）
[ ] 资源正确释放（RAII）
✅ 配置管理
[ ] 硬编码参数提取到配置文件（默认yaml格式文件并集中到config文件夹下面管理）
[ ] 配置项有合理默认值
[ ] 配置变更不需重新编译
✅ 日志输出
[ ] 统一格式：[模块名] 消息
[ ] 区分级别（info/warn/error）
[ ] 关键步骤有日志
[ ] 不在循环内打印日志（性能）
✅ 代码质量
[ ] 无魔法数字，使用命名常量
[ ] 函数职责单一
[ ] 避免重复代码（DRY原则），灵活使用设计模式
[ ] 使用类型安全的枚举
[ ] 智能指针管理资源
